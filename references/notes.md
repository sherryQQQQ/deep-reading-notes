# 笔记模式

把来源记录与个人判断分开，使笔记既能追溯，又能脱离原文复用。

## 笔记类型

- `source`：书目、来源范围和阅读状态；一份来源一条。
- `literature`：忠实压缩某一章节或论证；可以包含摘录。
- `concept`：定义、边界、相近/相反概念。
- `claim`：一个可争论主张及其证据和反证。
- `question`：未解决问题、假设与所需证据。
- `evergreen`：用自己的话表达、能独立成立且可连接的长期知识。

默认先产出 1 条 source/literature 笔记，再仅把最有复用价值的内容拆为 1–5 条原子笔记。不要把每个段落都原子化。

## 原子笔记质量

一条原子笔记应：

- 标题表达一个判断或清晰概念，而不是笼统主题。
- 正文开头用自己的话给出结论。
- 包含最少充分证据，并链接回来源与定位。
- 说明适用边界、反例或置信度（确有需要时）。
- 链接到真正相关的旧笔记，并说明关系：支持、反驳、延伸、例证或依赖。

## Markdown 数据契约

创建文件时使用这些字段；没有值的可省略：

```yaml
---
id: "20260922-meaningful-slug"
title: "标题"
note_type: "evergreen"
source_id: "可追溯来源"
locators: ["p. 12", "ch. 3"]
tags: ["领域/主题"]
status: "processed"
created: "2026-09-22"
---
```

正文建议顺序：核心陈述、证据、边界/疑问、关联。只有真实存在的内容才保留相应标题。

## 连接旧笔记

先按标题、别名和标签查找已有笔记。只有关系可用一句话说清时才建立链接，避免仅因共享标签而互链。找不到旧笔记时提出建议，不虚构路径。

## 使用脚本

需要创建本地 Markdown 文件时，可将内容写成 UTF-8 JSON：

```json
{
  "title": "官僚制通过可预测规则换取协调规模",
  "note_type": "evergreen",
  "source_id": "weber-vocation",
  "locators": ["p. 42"],
  "tags": ["社会学/官僚制"],
  "status": "processed",
  "body": "核心陈述……\n\n## 证据\n……"
}
```

然后调用 `scripts/render_note.py`。不要用脚本覆盖用户已有文件。
