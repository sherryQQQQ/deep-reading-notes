# 分类与标签

分类用于缩小检索空间；标签用于建立横向连接。优先使用用户已有体系。

## 默认维度

只使用能支持未来检索的维度，不必全部填写：

- `domain`：稳定领域，如社会学、产品管理、机器学习
- `topic`：具体主题，如官僚制、用户留存、因果推断
- `material_type`：book / paper / article / report / lecture / note
- `note_type`：source / literature / concept / claim / question / evergreen
- `status`：inbox / reading / processed / revisit
- `method`：案例、实验、综述、理论、评论等

## 决策规则

1. 每份材料选择一个主分类；需要时增加一个次分类。
2. 默认 3–7 个标签。优先已有标签，避免同义词并存。
3. 标签用具体名词短语；不要混入“重要”“有趣”等评价词。
4. 把作者、年份、文件格式放进元数据，而不是主题标签。
5. 对不确定分类给出候选与置信度，不凭单个关键词定类。

## 新体系的最小起点

用户没有体系时，先给出小而可扩展的两层结构：

```text
领域 / 主题
```

再配 `material_type`、`note_type`、`status` 三个受控字段。不要一开始建立多层目录树；等真实材料暴露出稳定聚类后再拆分。

## 批量分类

先从样本归纳候选词表，再统一分类全量。输出无法确定的项目清单，避免为了完整率制造虚假精度。合并标签时列出 `旧标签 → 规范标签` 映射，未经用户授权不改动原文件。
